## ★大前提（絶対ルール）

**迷ったら、すぐAIに聞きます。一人で悩まない。**

| 場面 | やること |
|------|--------|
| 操作で迷った／エラーが出た | Claude Code（AI）に状況を貼って相談する |
| 原因の特定 | AIに任せる（エラーメッセージ・スクリーンショットを渡す） |
| 解決方法の検討と実行 | AIに任せる（「直して」と投げてOK） |
| 「これで合ってる？」の確認 | AIに見てもらう |
| 公開後のテスト・レポート出力 | AIにまとめてやらせる（ステップ5-AI 参照） |
| 復旧・バックアップからの戻し | AIに「ステップ2のバックアップから戻したい、手順を出して」と投げる |

**運用ルール**: 「自分で考えて止まる」より「AIに聞いて進める」を優先。相談文は丁寧に書かなくてOK。「○○で詰まった、どうしたらいい？」レベルで投げる。スクリーンショット添付推奨。

## ステップ1｜事前準備（必要な情報を3つ集める）

公開作業を始める前に、以下の5項目（1-A 〜 1-E）をすべてチェック・受領します。1つでも漏れていると後工程で詰まります。

### 1-A. 提案・合意フェーズの完了確認

- [ ] 提案書／提案HTML（複数案：例 ELEGANT_WHITE / HERITAGE_DARK / URBAN_MUSIC 等）をクライアントに共有済み
- [ ] クライアントが採用案を選定済み（メール／議事録に記録あり）
- [ ] 脆弱性診断レポートを事前にクライアントへ提示済み（赤／黄／緑の項目別に対応方針を合意）
- [ ] 議事録（Tactiq等での文字起こし）を【案件フォルダ】／議事録/ に保存済み
- [ ] 「最終確認OK」のクライアント返信が記録に残っている
- [ ] 修正対応表（修正ID／ステータス／スクショ／修正事項／修正確認）の運用が始まっている

これらが揃っていない場合、本手順書の作業には進まず営業フェーズへ戻します。

### 1-B. WordPress管理画面のログイン情報（必須3点）

お客様から以下の3点を受領します：

1. WordPress管理画面のログインURL（形式: `https://【対象ドメイン】/wp/wp-login.php` または `/wp-admin/`）
2. 管理者ID（ログイン名）
3. 管理者パスワード

**【ヒント】受け取った情報は 1Password Teams の Vault `Client-{client-slug}` に保管。Drive や共有チャットに直接貼らない。**（1Password導入前は `C:\Users\hashi\.vaizo\secrets\` に保管）

### 1-C. 周辺アカウント受領（優先度A）

- [ ] ドメイン管理画面の権限（DNS設定／SSL強制／サブドメイン設定）
- [ ] レンタルサーバー管理画面（Xserver等。SSL常時化／サーバー設定／ファイルアップロード／HSTS設定）
- [ ] Google Analytics 4 管理者権限
- [ ] Google Search Console 権限（インデックス管理／公開後のURL検査）
- [ ] Google Tag Manager 管理者権限
- [ ] Google広告アカウント管理者権限（運用案件のみ）
- [ ] Google ビジネスプロフィール管理者権限（MEO案件のみ）

### 1-D. 写真・素材の受領状況の確認

- [ ] 全画像が「圧縮済み」かつ「ページ内の用途がわかる名前」にリネーム済み
- [ ] 【案件フォルダ】／01_WEBサイト刷新サービス／最新版／images に最終版が配置済み
- [ ] 受領追加写真（途中差し替え）がある場合は最終HTMLにすべて反映済み
- [ ] ロゴデータ（AI／SVG／高解像度PNG）が揃っている

### 1-E. クライアント連絡待ち項目の管理

公開直前まで決まっていなくても進められますが、本番反映前に必ず確定が必要：

- [ ] 問い合わせメール送信先の最終確定（誤設定はリード喪失、影響度: **高**）
- [ ] 予約Google CalendarのID／共有URL（カレンダー機能がある場合）
- [ ] GTMコンテナID（既存テーマで設定済みなら不要）
- [ ] ファビコン／apple-touch-icon
- [ ] JSON-LD Eventの実データ（イベント情報を載せる場合）

未確定項目は 【案件フォルダ】／公開作業/連絡待ちチェックリスト_YYYYMMDD.md に一覧化し、クライアントへの催促フローを回します。

## ステップ2｜現行サイトのバックアップを取る（最重要）

**【なぜやるか】** 公開後にデザインの崩れや不具合が起きたとき、すぐに元の状態に戻せる「保険」をかけておくため。バックアップを取らずに公開して問題が起きると、最悪の場合お客様のサイトが見られなくなります。

このステップでは「念のため重ねて取る」ことを推奨。3種類のバックアップを順番に取得します。

### 2-1. ［推奨］All-in-One WP Migration でサイト全体をバックアップ

1. 左メニュー「All-in-One WP Migration」→「エクスポート」
2. 「サイトのエクスポート先」をクリック → リスト表示
3. 「ファイル」をクリック
4. 「サイトを今すぐダウンロード」ボタンが出たら押して `.wpress` ファイルをPCに保存
5. Driveの【案件フォルダ】／公開作業／バックアップ_YYYYMMDD/ に保存

**戻し方**: 同じプラグインの「インポート」から保存した `.wpress` をドラッグ＆ドロップで復元。

### 2-2. ［二重保険］WordPress標準のエクスポート

1. 左メニュー「ツール」→「エクスポート」
2. 「すべてのコンテンツ」を選択
3. 「エクスポートファイルをダウンロード」→ XMLファイル取得
4. Driveのバックアップフォルダに保存

### 2-3. ［ピンポイント］編集対象ページの本文をテキストファイルに保存

1. 左メニュー「固定ページ」→「固定ページ一覧」→【対象固定ページ】を開く
2. 本文（HTML）の枠内をクリック → Ctrl+A → Ctrl+C
3. メモ帳に貼付 → `【対象固定ページslug】_backup_YYYYMMDD.html` で保存
4. Driveのバックアップフォルダに保存
5. 右側「リビジョン: ◯」の数字も控える（戻すとき使う番号）

**【3種類のバックアップ・まとめ】**
- 2-1（All-in-One WP Migration）→ サイト全部の完全コピー。最終的な保険
- 2-2（標準エクスポート）→ コンテンツ部分のみのコピー
- 2-3（本文コピー）→ 今回触るページだけのピンポイント保険。すぐに戻せる

**【絶対のルール】** 3つのファイルすべてをDriveの「公開作業／バックアップ_YYYYMMDD」フォルダにアップしてから、次のステップに進みます。

## ステップ3｜画像をダウンロードしてWordPressにアップロードする

### 3-1. 画像をダウンロード（圧縮・リネーム済みの最終版）

**【前提（実施済み）】**
- お客様と同意済みのデザインで使われている画像は、すべてVAIZO側で「圧縮」と「ページのどこに使うかわかる名前」へのリネーム作業を完了している
- 最終版HTMLファイルの画像パスは、リネーム後のファイル名にすべて差し替え済み

1. Google Drive【案件フォルダ】／01_WEBサイト刷新サービス／最新版／images を開く
2. フォルダごと「ダウンロード」→ ZIP取得
3. ZIPを解凍（extra / gallery 等のフォルダ確認）

### 3-2. WordPressの管理画面にログイン

【WP管理画面URL】をChromeで開く → ID/パスワード入力 → ログイン。

### 3-3. ダッシュボードからメディアへ移動

左メニュー「メディア」をクリック。

### 3-4. 画像を一括アップロード

1. 「メディアファイルを追加」→ グレーの大きな枠が表示
2. 解凍した画像フォルダの中身を全選択 → ドラッグ＆ドロップ
3. 緑色のチェックマーク確認

**【ポイント】**
- 1度に大量にアップすると失敗する → 10〜15枚ずつ分けて
- 同名ファイル衝突時は自動で `-1.jpg` 等が付く。差し替えたい場合は古いものを先に削除
- 1ファイル最大1GBまで

### 3-5. アップロード結果を確認

「メディア」→「ライブラリ」で一覧表示。アップした画像が並んでいれば成功。

## ステップ4｜WP最適化版の作成・デモ確認・本番貼り付け

このステップは、（A）最終版HTMLを WordPress 用に最適化 → （B）デモ環境で動作確認 → （C）OKなら本番に貼り付け、の3段階で進めます。

スタンドアロンHTMLをそのままWPに貼ると、テーマの `<head>`/`<header>`/`<footer>` と重複してレイアウトが崩れたりCSS衝突を起こすため、必ず「WP最適化版」を作ってデモで確認してから本番に貼ります。

### 4-pre. WP移行前チェックシート（事前監査・必須）

最終版HTMLを最適化に進める前に、AIに「監査」させて何が衝突するか・何を書き換えるべきかをリスト化。

**【AIに事前監査を依頼するプロンプト】** → [`templates/wp-prompts/04-pre-audit.md`](../templates/wp-prompts/04-pre-audit.md)

監査項目（A〜J）:
- A. 構造的問題（`<DOCTYPE>`/`<html>`/`<head>`/`<body>`/`<header>`/`<footer>`/`<nav>` の有無と重複）
- B. 画像パス（相対パス・絶対URL・外部CDN・GitHub Pages URL等）
- C. 外部URL／canonical／JSON-LD（書換が必要なURLを全箇所リスト化）
- D. CSP／セキュリティヘッダ
- E. 動的要素／フォーム／カレンダー
- F. **統合方式の判断**（[`decision-trees/wp-integration-method.md`](../decision-trees/wp-integration-method.md) 参照）
- G. WPプラグイン干渉（Yoast SEO／Page Builder／キャッシュ系）
- H. QAチェックリスト
- I. クライアント連絡待ち項目
- J. リスクと対応

**統合方式 選択の判断基準**:

| 方式 | 評価 | 適用条件 |
|------|------|---------|
| **A: カスタムページテンプレート（page-{slug}.php）** | ★★★★★ | テーマファイル編集可能、PHP書ける担当者あり |
| B: 固定ページ＋Custom HTMLブロック | ★★ | テーマ編集権限なし。CSS衝突に注意・スコープ化必須 |
| C: ショートコード化 | ★★★ | 複数ページで再利用したい |
| D: 別ドメイン／サブディレクトリで静的HTML | ★ | 最終手段 |

詳細フローチャート: [`decision-trees/wp-integration-method.md`](../decision-trees/wp-integration-method.md)

### 4-0. WP最適化版HTMLの作成とデモ確認

**【AIにWP最適化を依頼するプロンプト】** → [`templates/wp-prompts/04-0-optimize.md`](../templates/wp-prompts/04-0-optimize.md)

最適化要件:
1. `<head>`内の meta / link / style を WP テーマと重複しないように整理
2. `<header>`/`<footer>`/`<nav>` はテーマと統合（削除）
3. インラインCSSは body スコープ化（`body.page-【slug】 .xxx { ... }`）
4. インラインJSはIIFEまたはモジュール化
5. canonical / og:url / twitter:url / JSON-LD を【公開URL】に書換
6. 画像src を WPメディアアップロード後のURL（`https://【対象ドメイン】/wp-content/uploads/YYYY/MM/`）に一括置換
7. CSP meta タグは WPサーバ設定と整合がなければ削除
8. GTM / GA タグは既存テーマで設定済みなら削除

**【AIにデモ環境を構築してもらう】**

- GitHub Pages にデプロイ（リポジトリは **必ずプライベート＋招待制**で運用。公開リポジトリだとコードが読まれて脆弱性を突かれる可能性）
- リポジトリ名: `{案件略称}-wp-demo`
- ブランチ: `main`
- パスワード保護する場合は staticrypt 等で

**【3段階デモ運用（推奨）】**

| 段階 | 内容 |
|------|------|
| ① クライアント確認用デモ | GitHub Pages プライベート + staticrypt保護。デザイン・コピー・写真の最終OKをもらう |
| ② 開発確認用デモ | ローカルWP or ステージングWPで実際にテーマ統合確認。CSS／プラグイン干渉を実証 |
| ③ 本番（4-1以降） | ②でAIテスト全項目OKならここに進む |

### 4-1. GitHubからWP最適化版HTMLをダウンロード

1. AIから渡されたGitHubリポジトリのURLを開く
2. `【最終版HTMLファイル】_wp.html` をクリック
3. 右上の「Raw」ボタン横のダウンロードアイコン → PCに保存

### 4-2〜4-4. メモ帳経由・本文クリア

1. ダウンロードしたHTMLをメモ帳で開く → Ctrl+A → Ctrl+C
2. 編集画面の本文枠で Ctrl+A → Delete
3. メモ帳ウィンドウは閉じずに残す（万一の再コピー用）

### 4-5. 新しいHTMLを貼り付け

空になった本文枠で Ctrl+V。

### 4-6. プレビューで見た目を確認

「変更をプレビュー」→ 別タブで確認:
- 写真がすべて表示されている
- 見出し・本文・テーブル等のレイアウトが崩れていない
- スマホ表示で崩れない（F12 → スマホアイコン）
- 電話番号タップ／メールリンクが押せる
- 予約・問い合わせなどのCTAが動く

**【プレビューで問題があったとき】** AIに「プレビューでこういう症状」とスクショを渡して原因特定を依頼。詳細: [`troubleshooting/wp-publish-issues.md`](../troubleshooting/wp-publish-issues.md)

### 4-7. 「更新」をクリックして本番反映

1. 編集画面右側「公開」ボックスの青い「更新」ボタンをクリック
2. 「固定ページを更新しました」と表示されれば本番反映完了

**【公開直後にやること】**
- 【公開URL】を別タブで開いて確認
- Ctrl+F5 でスーパーリロード（古い表示が残らないようにキャッシュを破棄）
- PCとスマホ両方で表示を確認

## ステップ5｜公開後のテスト（公開直後に必ず実施）

公開ボタンを押したら終わりではありません。「ちゃんと動いているか」を必ずテストします。

### 5-AI. ［★最推奨・最速］AIに全自動でテストさせる

Claude Code に [`templates/wp-prompts/05-ai-test.md`](../templates/wp-prompts/05-ai-test.md) のプロンプトをそのまま貼り付けて送信。AIがPlaywrightで全リンク・全ボタン・全機能・レスポンシブ・Lighthouseまで自動チェック。

チェック項目:
1. 全リンクをクリック → 404・遷移先ズレ検出
2. 全ボタン（CTA・予約・問い合わせ・印刷）の動作確認
3. 電話（`tel:`）／メール（`mailto:`）リンク起動確認
4. ギャラリー: フィルター切替・ライトボックス
5. 見積シミュレーター動作確認
6. レスポンシブ: 320 / 375 / 414 / 768 / 1024 / 1280 / 1920 px
7. Lighthouseスコア（モバイル＋デスクトップ）
8. ブラウザコンソールエラー

合格基準:
- すべてのリンク 200 OK／想定先に遷移
- すべてのCTA・ボタンが動作OK
- レスポンシブ 全幅でレイアウト崩れなし
- Lighthouse モバイル パフォーマンス70以上 ／ LCP 2.5秒以内
- コンソールエラー 0件

### 5-メール. メール宛先のテスト送信（公開前必須・リード喪失防止）

問い合わせフォームのメール宛先設定ミスは「リード喪失」として影響度が最も高い項目です。

1. 本番ページの問い合わせフォームを開く
2. テストデータ（件名「公開前テスト送信」、本文「テスト送信。気にせず削除してください。」）で送信
3. クライアントに「いまテストメールを送ったので受信を確認してください」と Slack／電話で連絡
4. クライアントから「届いた」の返信をもらえれば確定
5. 届かない場合は WP管理画面のフォーム設定（Contact Form 7 等）の宛先設定を確認 → 修正 → 再送信
6. クライアントに送信ログ・受信スクショを残してもらい、案件フォルダに保存

### 5-1〜5-7. 手動チェック（AI不可時のフォールバック）

5-AI で全項目OKなら、5-1〜5-7 はスキップして 5-8 に進んでOK。

- 5-1. キャッシュ破棄（Ctrl+F5）
- 5-2. PCブラウザでの見た目チェック
- 5-3. スマホ表示のチェック
- 5-4. クリック・タップ動作チェック
- 5-5. 見積シミュレーター／予約カレンダー等の独自機能チェック
- 5-6. SEO・SNS表示の確認（Twitter Card / Facebook Debugger / GSC URL検査）
- 5-7. 表示速度のチェック（Lighthouse モバイル＋デスクトップ）

### 5-8. 関係者への連絡・社内記録

1. お客様に「公開完了報告」を連絡（[`templates/delivery-reports.md`](../templates/delivery-reports.md) 参照）
2. Driveの【案件フォルダ】／公開作業／公開記録_YYYYMMDD.md に以下を残す:
   - 公開日時
   - 公開URL
   - 5-2〜5-7のチェック結果（OK/NG）
   - スクリーンショット（公開直後のPCとスマホ表示）
   - バックアップファイルの場所（ステップ2で取った3つ）
   - トラブル時の連絡先（案件CTO・担当開発者）

### 5-トラブル. 公開後にトラブルが見つかったら

1. **まずAIに状況を渡す**（スクショ＋エラー文）→ 原因特定と復旧手順を出してもらう
2. 慌てない。ステップ2で3重のバックアップを取っているので必ず戻せる
3. 軽微（崩れ等）→ ステップ4-4でクリア → ステップ2-3のテキストを貼り戻す → 「更新」
4. 重大（真っ白／500エラー等）→ All-in-One WP Migrationの「インポート」から、ステップ2-1の `.wpress` を復元
5. 復元したらお客様に「一時的に表示が乱れたが復旧した」旨を即報告。原因を調べてから再公開

詳細: [`troubleshooting/wp-publish-issues.md`](../troubleshooting/wp-publish-issues.md)

## 困ったときは

**まず最初にやること: AIに相談する**

状況のスクリーンショット＋エラーメッセージをAIに貼って、「原因と対処を出して」と投げる。

**よくあるトラブル（参考。最終判断はAIに）**:

| 症状 | 第一手 |
|------|-------|
| ログインできない | ID/パスワード再確認、何度も間違えるとロック。AIに「IPロック解除方法」 |
| 画像のアップロードでエラー | 容量制限の可能性。サイズを下げて再試行。AIにスクショ＋エラー文 |
| ページが真っ白／500エラー | ステップ2-1の `.wpress` から即復元 |
| 崩れ・表示異常 | ステップ4-4でクリア → ステップ2-3の本文バックアップを貼り戻す |

**それでも解決しなかったとき**:
- 案件CTO（櫻井理也）にSlack DM
- AIとのやり取りログを一緒に共有すると引き継ぎが格段に早くなる
