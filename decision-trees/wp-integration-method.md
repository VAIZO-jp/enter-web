# 判断フロー：WP統合方式の選択（A / B / C / D）

> [`handbook/04-wp-publish-guide.md`](../handbook/04-wp-publish-guide.md) Step 4-pre F項 から参照される判断ツリー。

---

## 4方式の評価

| 方式 | 評価 | 適用条件 | 主リスク |
|------|------|---------|---------|
| **A: カスタムページテンプレート（page-{slug}.php）** | ★★★★★ | テーマファイル編集可 + PHP書ける担当者あり | テーマアップデートで上書きされる可能性（子テーマ化必須） |
| **B: 固定ページ + Custom HTMLブロック** | ★★ | テーマ編集権限なし／触りたくない | CSS衝突多発、JS干渉、テーマ `<header>`/`<footer>` 重複 |
| **C: ショートコード化** | ★★★ | 複数ページで再利用したい | プラグイン依存、保守性が下がる |
| **D: 別ドメイン／サブディレクトリで静的HTML** | ★ | 他案で対応不可、最終手段 | SEO効果分散、ブランド統一性低下、運用二重化 |

## 各方式の実装メモ

### 方式A: カスタムページテンプレート

```php
<?php
/*
Template Name: V/ENTER WEB - {{ページ名}}
*/
?>
<!-- WPテーマの header / footer は呼ばない -->
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
  <?php wp_head(); ?>
  <!-- カスタムCSS, OGP, JSON-LD はここに -->
</head>
<body>
  <!-- WP最適化版HTMLの本文をここに -->
  <?php wp_footer(); ?>
</body>
</html>
```

- 配置先: `wp-content/themes/{子テーマ}/page-{slug}.php`
- 固定ページ編集画面から「テンプレート」で選択
- 子テーマ必須（親テーマ更新で消えないように）

### 方式B: Custom HTMLブロック

- 編集画面で「カスタムHTML」ブロックを追加
- インラインCSSは `body.page-{slug} ...` で必ずスコープ化
- JSは IIFE で囲って衝突回避
- テーマ `<header>`/`<footer>` は表示されたまま（重複しないこと）

### 方式C: ショートコード

```php
function venter_lp_section_shortcode() {
  ob_start();
  ?>
  <!-- HTML本文 -->
  <?php
  return ob_get_clean();
}
add_shortcode('venter_lp', 'venter_lp_section_shortcode');
```

- 固定ページ・記事内で `[venter_lp]` で呼び出し可能
- 子テーマ `functions.php` または専用プラグイン化

### 方式D: 別ドメイン／サブディレクトリ

- Vercel / GitHub Pages / S3+CloudFront 等で静的ホスト
- メインドメインからリンクのみ
- canonical で SEO 影響を最小化

## 過去案件の実例

| 案件 | 採用方式 | 結果 |
|------|---------|------|
| 仙台レトロバックページ | 方式B（Custom HTML） | mailto事故等のリグレッションあり、最終的に整理して公開 |
| BAR NOIR デモ | 方式A前提（ステージングは静的） | デモ段階のため未統合 |
