# 判断フロー：エスカレーション順

> 詰まったとき・困ったときの「誰に・どう連絡するか」のフローチャート。

---

## エスカレーション順

```
Step 1: 自力 + AI で 30分試行
   ├── 解決 ✓ → 完了。学びを troubleshooting/ に追記PR
   └── 30分経過 → Step 2

Step 2: 案件CTO（櫻井理也）に Slack DM
   ├── 内容: 状況・スクショ・AIとのログ・試したこと
   ├── 反応1時間以内 → 解決へ
   └── 反応なし → Step 3

Step 3: #事業部別_enter-ai でメンション @here
   ├── 関連メンバー全員に共有
   ├── 反応30分以内 → 解決へ
   └── 反応なし or 緊急 → Step 4

Step 4: 橋本CEO に Slack DM or 電話
   ├── 緊急時のみ（通常は Step 2-3 で対応）
   └── 連絡先: 1Password共有 Vault に格納
```

---

## ケース別のエスカレーション先

| ケース | エスカレーション先 |
|-------|-----------------|
| 技術的な詰まり（実装・デバッグ） | 櫻井CTO → #claudeworks → 橋本CEO |
| WP公開作業中のトラブル | 櫻井CTO → #事業部別_enter-ai |
| クライアントからのクレーム | 小野寺・櫻井みどり（30分以内）→ 橋本CEO（2時間以内） |
| 脆弱性レポートの削除依頼 | 24時間以内に 小野寺・櫻井みどり が返信 → ブラックリスト永久登録 → 櫻井CTO に通知 |
| 法的相談（不正アクセス禁止法・契約・個人情報） | 橋本CEO → 顧問弁護士 |
| 経理・支払い | #経理部_経費精算-仕訳 |
| 業務委託（OneBe）の調整 | #all-onebe-vaizoアライアンスチーム |
| アカウント発行・権限 | #情報システム部 |

## 緊急時（公開直後の致命的トラブル）

例: 公開後にサイトが真っ白になった、500エラーが頻発、個人情報が露出した

```
1. まず深呼吸（2秒）
2. ステップ2-1のバックアップ（.wpress）から All-in-One WP Migration で即復元
   ※ 慌てない。バックアップを取っているから戻せる
3. 復元したらクライアントに「一時的に表示が乱れたが復旧した」旨を即報告
4. 櫻井CTO + 橋本CEO に Slack DM で並行報告
5. 原因調査は復旧後に落ち着いて行う
6. 学びを troubleshooting/ に追記PR
```

詳細: [`troubleshooting/wp-publish-issues.md`](../troubleshooting/wp-publish-issues.md)

## エスカレーション時の伝え方

良い例:

> 仙台レトロバックページ案件で公開作業中。
> Step 4-6 のプレビューで、ヘッダーがテーマと二重表示されている。
> AIに3回直してもらったが解決せず。
> スクショ添付：[image]
> AI とのやり取りログ：[link]
> 状態: 公開ボタンは押していない。Step 2-3 のバックアップは取得済み。
> 相談内容: 方式B → 方式A に切り替えるべきか、別の対処があるか、どちらか判断したい。

ダメな例:
> 動かない、助けて

→ 状況・試したこと・期待する判断 の3点を必ず添える。
