CLIENT

クライアント提供。受領後、原本のまま保管 + 圧縮版を別フォルダ。

  • SNS投稿写真（権利確認必須）
  • 過去パンフレット用素材
  • 店内撮影写真

PHOTOGRAPHER

撮影手配。Sランク案件で予算がある場合。1日5万〜15万。

  • VAIZO提携カメラマン
  • 業態に応じた撮影スタイル指定
  • 納品: 高解像度RAW + JPG

STOCK

無料・有料フォトストック。商用利用可・クレジット表記要否を必ず確認。

  • Unsplash / Pexels（無料）
  • Photo AC（日本人モデル多）
  • Adobe Stock / iStock（有料）

AI

方向性確認のみ。実装には実画像（撮影 or ストック）を使用。

  • Midjourney（ムードボード補完）
  • DALL-E（ラフ案）
  • SVG/CSS で抽象表現（Codex生成）
SECTION 04

MCP Toolbox

いつ・どのMCPを使うか
site-renewal

サイトリニューアル特化

既存サイトのコンテンツ抽出・デザイン参照とのマージ・16項目品質管理。リニューアル案件のメインMCP。

extract_content_map extract_design merge_and_renew quality_check
USE: STEP 03 / 04 / 06
web-cloner

サイト全体をクローン

競合サイトのデザイン解析、ローカル再現、A11y/SEO/セキュリティ監査、Wireframe生成。リサーチ初期フェーズ。

mirror_site capture_screenshots audit_site design_review
USE: STEP 03 / 06
figma-to-code

Figma完全再現

Figma案件のみ。SVG修正・回転楕円マスク・座標自動計算・スクショ比較で完全再現を実現。

analyze_sections generate_html_css screenshot_compare
USE: STEP 04（Figma案件のみ）
Codex CLI

実装ドラフト担当

業態別プロンプト雛形から初版生成。Claude→Codex→Claudeの直列で並行編集を避ける。

codex exec 非対話モード必須
USE: STEP 04
Claude Code

司令塔・統合

仕様整理、Codex出力レビュー、最終採否、品質チェック、直接Edit。すべての判断を担う。

Read Edit Bash Playwright MCP
USE: ALL STEPS
Playwright

自動テスト・スクショ

全リンク・CTA・レスポンシブ・Lighthouse・コンソールエラー検知を全自動。

page.goto page.screenshot Lighthouse
USE: STEP 06 / 08
SECTION 05

Codex Build Order

Codexで作る標準7手順
01
仕様確定 — brief.md を案件直下に書く
対象ファイル / 入出力仕様 / 制約 / 完了条件 (DoD) を箇条書き。所要時間 5〜10分。
02
プロンプト雛形をコピー
業態に応じて bar / live-house / corporate / beauty-salon / clinic / real-estate / school から選択。
cp templates/codex-prompts/bar-or-restaurant-fv.md ./codex_prompt.md
03
プレースホルダ {{...}} を埋める
屋号・業態・キーワード・配色・電話番号など。3キーワードはデザインリサーチで決まったものを使う。
04
Codex 非対話モードで実行
起動前に codex --version で疎通確認。セッション切れは無音失敗するので必須。
codex exec --skip-git-repo-check --cd "$PWD" --output-last-message "./codex_out.md" "$(cat ./codex_prompt.md)"
05
Claude Code でレビュー
codex_out.md を Claude が読み、仕様充足性を判定。修正は Claude が直接 Edit。Codex に再投げしない（直列維持）。
06
site-renewal MCP で品質チェック
16項目（A11y・SEO・パフォーマンス・ブランド整合等）を自動診断 + 修正提案。
// MCP: site-renewal__quality_check {site: "./index.html"}
07
デモ環境構築
GitHub Pages（プライベート + staticrypt）または Vercel に Preview デプロイ → クライアント確認。
// MCP: site-renewal__deploy_vercel {repo: ".", projectName: "{slug}-demo"}
